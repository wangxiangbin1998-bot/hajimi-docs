哈吉米 API 使用文档

本站（哈吉米 API，https://hajimi.men）的接入与配置教程。照着做，基本不会出问题；做不通时，把你卡住的步骤和报错截图发到 QQ 群（群号见站内公告），管理员会看。

先记住两个地址

用途 地址
控制台（注册、充值、建令牌、查用量） https://hajimi.men
接口地址（填进各种工具里的） Claude 类工具填 https://hajimi.men ；OpenAI 兼容工具填 https://hajimi.men/v1

填错这两个地址是新手最常见的翻车点，各篇教程里还会再提醒。

令牌先选对分组

建令牌时要选分组，分组决定你能用哪些模型、按什么倍率扣费：

  • 用 Claude Code / Claude Desktop → 建 Claude 分组的令牌（速刷、正价池、Max 满血三档，按需选）
  • 用 Codex / ChatGPT → 建 GPT 分组的令牌（小杯、中杯、大杯三档）
  • 用国产模型 → 建 国模分组的令牌

选错分组会出现没模型、403 之类的报错。各分组当前包含的模型和价格，以站内「模型广场」实时展示为准。

充值与计费说明

余额是什么

本站余额以美元（$）计价显示。调用模型时按「模型基础价 × 令牌分组倍率」扣费，每笔消费都能在控制台「使用日志」里查到（模型、Token 数、金额、时间）。

怎么充值

登录后进入左侧「钱包」：

  1. 在线充值（以钱包页实际开放的为准）：选预设金额或输自定义金额，选支付宝/微信付款，支付成功后余额自动到账
  2. 兑换码充值：有兑换码的，在钱包页输入兑换码即可到账（活动、群福利发的都是这种）

充值比例与可付金额以钱包页实时显示为准；支付时如果没弹出支付页面，先关掉代理再重试。

免费额度

  • 每日签到：个人中心签到可领小额额度（每日一次，金额随机）
  • 邀请奖励：通过邀请链接注册的新人完成注册后，邀请双方按站内规则得奖励额度（以钱包页/公告为准）

省钱提示

  • 余额低于你设的提醒阈值时，系统会发邮件提醒，别等到调用一半断粮
  • 同一模型在不同分组价格不同：不赶时间用便宜分组，干活求稳用高档分组
  • Claude 类模型用好缓存（会话别频繁新开、系统提示保持稳定）能明显降费，细则见《服务特定条款》

模型广场使用说明

模型广场是本站的价目表：每个分组有哪些模型、多少钱、速度怎么样，都在这看。配任何工具之前，先来这里确认两件事——你要的模型在哪个分组、准确的模型名是什么，能省掉一半的"模型不存在"报错。

入口：控制台右上角「模型广场」，登录后可见。

怎么看

  • 左侧「可用令牌分组」：点某个分组，右侧只剩这个分组能用的模型。分组名后面带的就是倍率（如 ×0.25）
  • 模型卡片：右上角小字是所属分组；卡片里有模型 ID（配置工具时原样复制这个）、输入 / 输出 / 缓存读取价格；底部是平台实测的吞吐、延迟和成功率（带采样时间，挑分组时可以参考）
  • 左侧「端点类型」：按请求协议筛选（anthropic、openai 等）——你的工具走哪种协议就筛哪种
  • 右上角「表格视图」：一次看全所有模型的价格，适合比价

倍率是什么意思

实际扣费 ＝ 模型基础价 × 分组倍率：

  • 倍率小于 1 是折扣：0.25 就是官方价的 2.5 折
  • 倍率大于 1 是加价档（如满血分组），买的是更好的池子和稳定性

同一个模型可能出现在多个分组里，价不同、池子不同：便宜档适合日常跑量，高档适合长任务和求稳，按活选，别只盯最便宜的。

和令牌的关系

建令牌时选的分组，决定这个令牌能调哪些模型、按哪档倍率扣费。所以顺序是：先在模型广场选好模型和分组 → 再去令牌管理建对应分组的令牌 → 最后把令牌配进工具。

服务状态与监控说明

想知道"现在能不能用、哪个分组快"，看这三个地方，不用问人：

1. 控制台概览 · API 信息

登录后的概览页有 API 信息区，显示接口地址和实时延迟检测。延迟明显变大或检测不通，说明线路或上游在波动，可以先换个分组试，或等几分钟再看。

2. 模型广场 · 模型卡片

每个模型卡片底部有平台实测的吞吐、延迟、成功率和采样时间。挑分组时除了看价格，也看成功率：某个分组成功率明显掉了，先避开它，用同模型的其他分组。

3. 你的使用日志

调用失败先查自己的「使用日志」：失败记录的时间、模型、分组都在，对照通用报错速查自查原因。日志里查不到的失败，多半是请求根本没到本站（本机网络/工具配置问题）。

维护与故障

计划维护和突发故障会在站内公告和 QQ 群同步。出现大面积报错时先看公告，没公告再带截图到群里问。

CC Switch · 通用步骤（下载与安装）

CC Switch 是一个开源的桌面小工具（项目地址：https://github.com/farion1231/cc-switch ），专门用来管理 Claude Code、Codex 等命令行工具的接口配置：图形界面里加好供应商，点一下就能切换，不用手动改配置文件。

本站没有在 CC Switch 里内置模板，但本站令牌页提供「一键导入」，效果一样，还更省事；手动添加的方法各分篇里也都写了。

下载安装

到 CC Switch 的 GitHub Releases 页面下载对应系统的安装包：

Windows

  • 普通电脑下载 CC-Switch-v版本号-Windows.msi 安装包
  • 不想安装就下免安装版 CC-Switch-v版本号-Windows-Portable.zip
  • ARM 机器选文件名带 arm64 的

macOS

  • 推荐用 Homebrew 安装：终端运行 brew install --cask cc-switch，以后升级用 brew upgrade --cask cc-switch
  • 也可以直接下 CC-Switch-v版本号-macOS.dmg；安装包是通用版，Apple 芯片和 Intel 芯片都能用，已签名公证，可直接打开

Linux

  • Debian/Ubuntu：到 Releases 页面确认最新版本号，下 CC-Switch-v版本号-Linux-x86_64.deb（ARM 机器换 arm64），用 sudo dpkg -i 文件名.deb 安装
  • Fedora 等 RPM 系把 .deb 换成 .rpm；其他发行版可下 .AppImage 直接运行
  • Arch Linux：paru -S cc-switch-bin

系统要求

  • Windows：Windows 10 及以上
  • macOS：macOS 12（Monterey）及以上
  • Linux：x86_64 或 ARM64，Ubuntu 22.04+、Debian 12+、较新的 Fedora 等

开始配置之前

  1. 先在本站（https://hajimi.men）注册账号、充值、建好令牌——用哪个工具，就建哪个分组的令牌（见文档首页的分组说明）
  2. 确认你的 Claude Code / Codex 命令行本身能正常启动（装 Node.js、装 CLI 的步骤见各工具官方说明）
  3. 然后按你用的工具看对应分篇：
  • Claude Code 配置
  • Codex 配置
  • Claude Desktop 配置

CC Switch · Claude Code 配置

前提：已装好 CC Switch 和 Claude Code，并且在本站建好了 Claude 分组的令牌。两种配法，任选其一。

方法一：一键导入（推荐）

  1. 登录本站，进入「令牌管理」，找到你建好的 Claude 分组令牌
  2. 点令牌旁的「一键导入」，在客户端列表里选 CC Switch
  3. 浏览器会唤起 CC Switch 并把地址和密钥自动填好，确认导入
  4. 在 CC Switch 左侧选 Claude Code，把刚导入的供应商点「切换」，卡片显示「使用中」
  5. 终端运行 claude，随便发一句话，能收到回复即成功

方法二：手动添加

  1. 打开 CC Switch，左侧栏选 Claude Code。页面上方有「直连 / 路由 / 聚合」三个标签，全程用 直连
  2. 点右上角「添加供应商」，选「自定义」手动填写：
  • 名称：哈吉米 API（随便起，认得出就行）
  • 请求地址：https://hajimi.men
  • API Key：粘贴你的 Claude 分组令牌
  1. 点「添加」保存
  2. 回到供应商列表，点这张卡片右侧的切换图标，显示「使用中」即切换完成
  3. 终端运行 claude 测试对话

最容易填错的地方

  • 请求地址不要带 /v1。Claude Code 填 https://hajimi.men；带 /v1 的地址是给 Codex 那类 OpenAI 兼容工具用的，填错了会直接报错
  • 也不要填成带路径的控制台页面地址，就填上面这一个根地址
  • 令牌要用 Claude 分组的。用 GPT 分组的令牌配 Claude Code，会出现没模型或 403

CC Switch · Codex 配置

前提：已装好 CC Switch 和 Codex，并且在本站建好了 GPT 分组的令牌。两种配法，任选其一。

方法一：一键导入（推荐）

  1. 登录本站，进入「令牌管理」，找到你建好的 GPT 分组令牌
  2. 点令牌旁的「一键导入」，在客户端列表里选 CC Switch
  3. 浏览器唤起 CC Switch 自动填好配置后，确认导入；模型列表按下面方法二第 3 步检查一遍（自动带入的模型可能不全）
  4. 在 CC Switch 左侧选 Codex，把供应商点「切换」，显示「使用中」
  5. 彻底重启 Codex（见文末注意），终端运行 codex 测试对话

方法二：手动添加

  1. 打开 CC Switch，左侧栏选 Codex，上方标签保持 直连
  2. 点右上角「添加供应商」，选「自定义」填写：
    • 名称：哈吉米 API
    • API Key：粘贴你的 GPT 分组令牌
    • API 请求地址：https://hajimi.men/v1
  3. 模型列表要手动加（点「获取模型列表」拿不到，直接点「+ 手动添加」补两行）：
    • 第一行：你要用的主模型，显示名和请求模型都填同一个模型 ID，例如 gpt-5.6-sol（可用模型以本站模型广场 GPT 分组实时展示为准）
    • 第二行：两列都填 codex-auto-review
    • 「自动审批模型」选 Codex 默认 (codex-auto-review)，和第二行对上
  4. 点「添加」保存，回到列表点卡片右侧切换图标，显示「使用中」、顶部提示「直连生效中」即完成

最容易填错的地方

  • 请求地址必须带 /v1：https://hajimi.men/v1。这点和 Claude Code 正好相反（那边不带），搞混是 Codex 配不通的头号原因
  • 如果自动审批时报错，把「自动审批模型」改成你的主模型再试
  • 切换供应商后必须彻底重启 Codex：切换前开着的 Codex 还在用旧配置。终端会话退出重开；桌面版要完全退出（macOS 用 ⌘Q，只关窗口不算）再打开；编辑器插件要重开窗口

CC Switch · Claude Desktop 配置

先分清：Claude Desktop（桌面客户端）和 Claude Code（命令行/插件）在 CC Switch 里是两个独立入口，配置互不相通，要分别配。这一页说的是桌面客户端。

前提：已装 Claude Desktop 和 CC Switch，在本站建好了 Claude 分组的令牌。

步骤

  1. 打开 CC Switch，在左侧应用切换器中选 Claude Desktop 入口
  2. 点右上角「添加供应商」，选「自定义」填写：
    • 名称：哈吉米 API
    • API Key：粘贴你的 Claude 分组令牌
    • 请求地址：https://hajimi.men（结尾不要带斜杠，更不要带 /v1）
    • 接入方式：保持 直连
  3. 填模型列表，两种方式任选：
    • 点「获取模型列表」自动拉取，拉到就不用管
    • 拉不到就点「添加模型」，到本站模型广场复制你要用的模型名粘进来；模型支持 1M 上下文的，把右侧「1M」勾上
  4. 点「添加」。回到列表如果这家还没被选中，点卡片右侧切换图标选中它
  5. 完全退出 Claude Desktop 再重新打开（它只在启动时读配置，只关窗口不生效），随便发一条消息测试

注意事项

  • 启动后顶部可能弹出一条网关（Gateway）登录告警，无视它，能正常收到回复就是配好了。判断标准只有一个：能不能对话
  • 配置由 CC Switch 写入，不要手动改 Claude Desktop 的配置文件，下次切换会被覆盖
  • 想恢复官方登录：在供应商列表里切回「Claude Desktop Official」即可，不需要 Key

CC Switch · 用量查询配置

配好之后，CC Switch 的供应商卡片上能直接显示本站余额，不用每次开网页查。

注意：用量查询用的不是配供应商时填的 API Key，而是本站的「系统访问令牌 + 用户 ID」，要单独生成、单独填。

步骤

  1. 打开 CC Switch，在供应商卡片右侧点「…」菜单，选「配置用量查询」（Claude Code 和 Codex 面板的操作一样）
  2. 打开「启用用量查询」，预设模板选 NewAPI
  3. 填三项：
    • 请求地址：https://hajimi.men
    • 访问令牌：登录本站，在「个人设置」里生成系统访问令牌，粘贴进来
    • 用户 ID：个人设置页顶部显示的用户 ID，照填
  4. 超时时间保持 10 秒，自动查询间隔保持 5 分钟（填 0 表示不自动查），下面的提取器代码由模板自动生成，不用改
  5. 点「保存配置」，回到供应商列表，卡片上就会出现余额

最容易填错的地方

这里的请求地址填控制台地址 https://hajimi.men，和配供应商时填的接口地址不是一回事，别互相照抄：

  • 供应商（Claude Code）：https://hajimi.men
  • 供应商（Codex）：https://hajimi.men/v1
  • 用量查询：https://hajimi.men（就是控制台本身）

三项凭证都留空的话，CC Switch 会退回用供应商的地址和 Key 去查，余额取不到——所以三项都要自己填。

ChatGPT 桌面版接入

ChatGPT 桌面版可以复用 Codex 的供应商配置。先按 Codex 配置 把 Codex 配好并切换到哈吉米，再看这一页。

直接复用（多数情况）

  1. 确认 Codex 已通过 CC Switch 切到哈吉米，且终端里能正常对话
  2. 安装并打开 ChatGPT 桌面版，它读到现有的 Codex 配置后即可直接使用，发一条消息测试

首次启动还出现登录页

  1. 先完全关闭 ChatGPT，确认 Codex 配置有效，再重新打开
  2. 仍出现登录页时，点「使用其他方式登录」
  3. 把本站 GPT 分组令牌粘贴到「OpenAI API 密钥」，点「继续」
  4. 进入后发一条测试消息，能回复即生效

切换供应商后没生效

在 CC Switch 里改过 Codex 配置后，ChatGPT 必须完全退出再重开（只关窗口它还留在后台用旧配置）：菜单选「文件 → Quit ChatGPT」，或按 Ctrl+Q（macOS 用 ⌘Q），再重新启动。

CC Switch CLI（命令行版，简版）

适合服务器、SSH、纯终端和自动化场景。图形界面够用的人看前面几篇即可。

CC Switch CLI 是独立项目（https://github.com/SaladDay/cc-switch-cli ），功能与桌面版对应：管理 Claude Code、Codex、OpenCode 等工具的供应商配置，带完整命令和终端界面（TUI）两种用法。

安装

macOS / Linux 一键脚本：

curl -fsSL https://github.com/SaladDay/cc-switch-cli/releases/latest/download/install.sh | bash

默认装到 ~/.local/bin，找不到命令时确认它在 PATH 里。Windows 到其 GitHub Releases 下载 cc-switch-cli-windows-x64.zip，解压后把 cc-switch.exe 放进 PATH 目录。

使用

cc-switch                                  # 进入 TUI 界面（首次配置推荐）
cc-switch --app claude                     # 直接进 Claude Code 的配置界面
cc-switch --app codex                      # 直接进 Codex 的配置界面
cc-switch provider list                    # 查看供应商列表（默认 Claude）
cc-switch provider current                 # 查看当前供应商
cc-switch provider switch <id>             # 切换供应商
cc-switch env tools                        # 检查本地 CLI 是否安装
cc-switch env check                        # 检查环境变量冲突
cc-switch update                           # 更新自身

管理非 Claude 的应用时，用全局参数 --app codex 等指定。

配置要点

  • 目标 CLI 先运行一次（如 claude --help）让它生成自己的配置目录，再切换供应商
  • 供应商选「自定义」添加：名称随意，Claude Code 的请求地址填 https://hajimi.men，Codex 填 https://hajimi.men/v1，API Key 用本站对应分组的令牌
  • 切换后没生效，先查环境变量：如果系统里设了 ANTHROPIC_API_KEY、OPENAI_API_KEY 等变量，工具会优先读变量、盖掉这里的配置，用 cc-switch env check 能查出来

进阶客户端 · OpenCode 配置

进阶客户端 · OpenClaw 配置

OpenClaw 是跑在服务器/Mac 上的个人 AI 助手网关（接 Telegram 等聊天软件使唤它干活）。这一页讲怎么把它的模型来源换成本站。适合 Linux 云服务器和 macOS 用户。

安装与初始化

终端运行官方安装脚本：

curl -fsSL https://openclaw.ai/install.sh | bash

安装向导里：选 QuickStart；供应商一步先选 Skip for now 跳过（装完再手动配本站）；其余选项（聊天适配器、Skills、Hooks）按你自己的需要选。

配置本站为模型供应商

编辑 ~/.openclaw/openclaw.json，在 models.providers 里加一家（用 Claude 模型为例）：

{
  "models": {
    "providers": {
      "hajimi": {
        "baseUrl": "https://hajimi.men",
        "apiKey": "粘贴你的Claude分组令牌",
        "api": "anthropic-messages",
        "models": [
          { "id": "模型广场里Claude分组的模型名", "name": "显示名随意" }
        ]
      }
    }
  }
}

要点：

  • 用 GPT 或国产模型时，把 api 改为 openai-completions，baseUrl 改为 https://hajimi.men/v1，令牌换成对应分组的
  • 模型 id 必须和模型广场里该分组的模型名完全一致
  • 在配置里把默认模型设为 hajimi/你的模型名（按 OpenClaw 的模型引用格式）

改完重启网关并测试：

openclaw gateway restart
openclaw tui

TUI 里能正常对话即成功（/quit 退出）。浏览器管理界面用 openclaw dashboard 给出的地址打开。

常见坑

  • 报模型不存在：模型 id 与广场不一致，或令牌分组不对
  • 改了配置没生效：没重启 gateway
  • 服务器上跑还想从外网开管理界面：自己用反向代理加 HTTPS，并按 OpenClaw 官方说明处理网关鉴权，不要裸奔暴露端口

Claude Code 常见问题

明明选的是贵的模型，账单里为什么会出现别的便宜模型

正常现象，不是配错了，也不是被多扣钱。

Claude Code 会在后台自己干一些小活：给对话起标题（历史记录里显示的那行字）、把太长的聊天记录压缩、派生子任务（Subagent）单独处理一小块工作。干这些小活时它会自己换一个便宜快的模型，不用你选的那个。所以使用日志里多出一些别的模型记录，是它自己在干活。

  • 这类钱一般很小（几分到几毛），不用管
  • 如果单笔大得反常（好几块以上），带上时间到来本站「使用日志」里对一下那笔的模型和金额，对不上就到 QQ 群找管理员
  • 子任务用哪个模型取决于子任务自己的配置，和主对话选的模型是两回事；/fast 只是同模型的更快输出模式，不涉及换模型

Claude Desktop 新建对话时为什么会自动调用一次模型

同样正常：新建对话发出第一条消息后，它会自动用一个小模型给这个对话生成标题（左侧对话列表里显示的那行字），关不掉，费用极小。日志里看到莫名的小额调用，多半就是它，别怀疑账号被盗。

在 VS Code 的 Claude Code 插件里怎么用

先保证命令行版 Claude Code 已按教程配好能用。然后给插件补一个配置文件：

  • Windows：按 Win+R 输入 %userprofile%\.claude 回车，打开该目录
  • macOS：在访达按 Command+Shift+G，输入 ~/.claude 回车

目录里如果没有 config.json 就手动新建，写入下面内容保存，再重启 VS Code：

{
  "primaryApiKey": "hajimi"

（值填任意非空字符串即可，这里只是让插件走命令行版的配置。）

报错 Unable to connect to Anthropic services

首次配置常见：Claude Code 还没完成它的初次确认流程。按系统运行下面命令，给配置文件打上"已完成引导"标记，然后重启 Claude Code。

Windows（命令行里运行 PowerShell 命令）：

powershell -Command "$f='%USERPROFILE%\.claude.json'; $j=Get-Content $f | ConvertFrom-Json; $j | Add-Member -NotePropertyName 'hasCompletedOnboarding' -NotePropertyValue $true -Force; $j | ConvertTo-Json | Set-Content $f"

macOS（终端运行，需要 jq，没有就先 brew install jq）：

jq '. + {"hasCompletedOnboarding": true}' ~/.claude.json > /tmp/tmp.json && mv /tmp/tmp.json ~/.claude.json

怎么切回 200K 上下文、顺便省钱

在 ~/.claude/settings.json（Windows 是 %userprofile%\.claude\settings.json）的 env 里加入下面几项（和已有配置合并，别覆盖掉你的令牌配置）：

{
  "env": {
    "CLAUDE_CODE_DISABLE_1M_CONTEXT": "1",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "CLAUDE_CODE_DISABLE_TERMINAL_TITLE": "1",
    "DISABLE_TELEMETRY": "1",
    "DISABLE_AUTOUPDATER": "1",
    "DISABLE_ERROR_REPORTING": "1",
    "CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS": "1"
  }
}

特别说一下 CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS：Claude Code 默认每次对话都把当前仓库的 git 状态（改了哪些文件等）塞进系统提示里。git 状态一变，缓存的命中就跟着失效，token 消耗和费用都会涨。关掉它，缓存更稳，同样的工作更省钱——本站几个 Claude 分组都是按缓存命中率定的价，这一项对账单影响很实际。

401 报错（Unauthorized / exceeded retry limit）

多半是本机残留的环境变量在跟 CC Switch 的配置打架。先检查：

  • Windows（cmd 运行）：cmd /c "if defined OPENAI_API_KEY (echo KEY=OK) else (echo KEY=MISSING) & if defined OPENAI_BASE_URL (echo URL=OK) else (echo URL=MISSING)"
  • macOS（终端运行）：[ -z "$OPENAI_API_KEY" ] && echo KEY=MISSING || echo KEY=OK; [ -z "$OPENAI_BASE_URL" ] && echo URL=MISSING || echo URL=OK

两个都显示 MISSING 是正常的，直接查配置；如果显示 OK，说明有残留变量在覆盖配置：Windows 用 cmd /c "setx OPENAI_API_KEY "" & setx OPENAI_BASE_URL """ 清掉，macOS 用 unset OPENAI_API_KEY OPENAI_BASE_URL（并检查 shell 配置文件里有没有写死）。

还不行，再核对两处：~/.codex/auth.json 里的 Key 是否完整正确、config.toml 里的 base_url 是否为 https://hajimi.men/v1。

403 报错（Forbidden）

按顺序自查：

  1. 令牌分组对不对：Codex 必须用 GPT 分组令牌；拿 Claude 分组的令牌来调 GPT 模型就是 403
  2. 模型在不在这个分组里：用模型广场确认该模型属于你令牌的分组
  3. 余额够不够：钱包余额不足也会拒
  4. 令牌状态：令牌被禁用或过期，去令牌管理里看一眼

都正常还 403，截报错图到 QQ 群找管理员。

Connection failed（连接失败）

先分清是本机网络问题还是配置问题：终端里运行 codex 直接对话测试——终端能用、插件不能用，就是插件/编辑器的问题，重启编辑器；终端也不能用，先关掉本机的代理工具再试，还不行换个网络环境试。都排除了还连不上，带报错截图到 QQ 群。

通用报错速查

先对着这张表自查，多数问题都是地址、分组、Key 三件事填错。

报错 含义 怎么处理
401 Unauthorized Key 不对或没带上 检查 Key 是否复制完整（前后别带空格）、是否用了已删除/禁用的令牌；用 CC Switch 的检查环境变量残留有没有覆盖配置
403 Forbidden 没权限 ①令牌分组和模型对不上（调 GPT 模型要用 GPT 分组令牌，调 Claude 要用 Claude 分组）②余额不足 ③令牌被禁用/过期
404 Not Found 地址填错 Claude 类工具应填 https://hajimi.men（不带 /v1）；OpenAI 兼容工具应填 https://hajimi.men/v1（带 /v1）。搞反了就是 404
模型不存在 / model not found 模型名不对或分组里没这个模型 到模型广场复制准确模型名；确认它在你令牌的分组里（有的模型只在特定分组有）
429 Too Many Requests 请求太频繁或上游正忙 降并发、等几十秒重试；持续出现就换个分组试试
500 / 502 / 上游错误 上游波动 等一两分钟重试；反复出现可以换同模型的另一个分组，或到 QQ 群看公告是不是在维护
Insufficient quota / 余额不足 钱包没钱了 到本站钱包充值；或检查令牌是否设了额度上限且已用满
一直转圈 / 超时 网络或长任务 先确认本机网络和代理设置；长任务本来就慢，等一等； consistently 超时就把工具彻底重启再试

自查都过了一遍还不行：把报错截图 + 你用的工具 + 令牌分组 + 大概时间发到 QQ 群，管理员按日志帮你对。

服务特定条款

生效日期：2026-10-28

本文件是《服务条款》的补充，约定各分组、各类调用的特别规则。与《服务条款》冲突时，以本文件为准。

一、计费口径

  1. 全部调用按 Token 用量计费，单价＝模型基础价 × 你令牌所在分组的倍率，以模型广场与使用日志的展示为准。
  2. 支持缓存的模型区分「缓存命中」与「缓存未命中」计价，命中部分价格更低；命中率取决于你的调用方式（如会话是否连续、系统提示是否稳定），平台不承诺固定命中率，分组说明中的缓存比例为经验参考值。
  3. 客户端软件（Claude Code、Codex 等）自动发起的辅助调用（生成标题、压缩上下文、代码审查、子任务等）同样计费，属正常消费，详见对应常见问题页。
  4. 预扣额度与实际消费有差额的，以结算后的使用日志记录为准。

二、Claude 分组

  1. 会话保持（粘性路由）默认开启：同一会话尽量走同一渠道以提高缓存命中；渠道故障时自动切换，切换后缓存可能短暂失效，属正常现象。
  2. Claude-Max 分组禁止蒸馏：不得将该分组的模型输出用于训练或蒸馏其他模型，不得用于违规「破甲」用途；违反者封号且余额不退（与令牌分组说明一致）。
  3. 标注为预览（preview）的模型稳定性不作保证，可能随时下线。

三、GPT 分组

  1. Codex 自动审批、联网搜索整理等客户端行为产生的调用按正常规则计费。
  2. 长上下文调用按站内公布的长上下文价格计费（见模型广场价格明细）。

四、国模分组

  1. 国产模型经兼容接口提供，不同客户端的适配表现可能有差异。
  2. 标注 preview 的模型为预览版，不保证稳定性与长期可用。

五、数据处理

  1. 你的请求内容经本平台转发至上游模型服务商处理，上游的处理适用其各自政策；本平台仅留存计费所需的元数据日志（时间、模型、用量、金额），细则见站内《隐私政策》。
  2. 请勿通过本平台发送你无权处理或不希望被上游处理的敏感个人信息。
